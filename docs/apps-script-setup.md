# Apps Script 共有のセットアップ手順

この手順は、麻雀アプリのルーム単位データをGoogleスプレッドシートで共有するための準備です。まずは「端末から手動で保存・取得」を行います。自動同期はまだ有効にしません。

## 事前に用意するもの

- 共有データの所有者になるGoogleアカウント
- Googleスプレッドシートを作成できるブラウザ
- 共有したい利用者のGoogleアカウント

点数データはスプレッドシートの所有者アカウントに保存されます。アカウントを変えるとWebアプリの所有権・保存先も変わるため、長く使うアカウントで作成してください。

## 1. 保存先スプレッドシートを作る

1. [Google Sheets](https://sheets.new) を開く。
2. ファイル名を `Mahjong Score Shared Data` など分かる名前に変更する。
3. シートを閉じずに、メニューから **拡張機能 → Apps Script** を開く。

Apps Scriptはこのスプレッドシートに紐付けます。共有APIは初回保存時に `rooms` シートを自動作成するため、表を手で作る必要はありません。

## 2. Apps Scriptのコードを貼り付ける

1. 開いたApps Scriptエディタで `Code.gs` の既存内容をすべて消す。
2. このリポジトリの [`apps-script/Code.gs`](../apps-script/Code.gs) の内容を貼り付ける。
3. 保存ボタンを押す（プロジェクト名は任意）。

このコードは、ルームを1行のJSONとして保存します。`revision` を持つため、古い端末からの保存で新しいデータを黙って上書きしません。

## 3. Google Cloudプロジェクトを準備する

1. Apps Scriptエディタ左下の **プロジェクトの設定** を開き、**Google Cloud Platform (GCP) プロジェクト** の番号を控える。（GCPプロジェクトをconsoleで作成）
2. **プロジェクトを変更** を押し、新しい**標準Google Cloudプロジェクト**を作成して紐付ける。
3. Cloud Consoleで同じプロジェクトを開き、**APIとサービス → ライブラリ** から **Google Apps Script API** を有効化する。
4. **OAuth同意画面**を作成する。テスト中は「外部」を選び、自分と共有メンバーのGoogleアカウントを**テストユーザー**に追加する。
5. **認証情報 → 認証情報を作成 → OAuth クライアント ID → ウェブアプリケーション**を選ぶ。
6. 「承認済みのJavaScript生成元」に次を登録する。
   - 開発時: `http://localhost:5173`
   - 公開時: `https://<GitHubユーザー名>.github.io`
7. 表示された**クライアントID**を控える。クライアントシークレットはブラウザアプリでは使わない。

## 4. API Executableとしてデプロイする

1. Apps Scriptへ戻り、**デプロイ → 新しいデプロイ**を押す。
2. 種類の選択から **API Executable** を選ぶ。
3. アクセスできるユーザーは、共有メンバーが使える設定を選ぶ（匿名公開は選ばない）。
4. デプロイ後、**プロジェクトの設定 → スクリプトID**を控える。

WebアプリURLの `/exec` は以後使いません。Execution APIでは、Googleログインで取得したOAuthトークンを使って関数を直接実行します。Apps ScriptとOAuthクライアントは同じ標準Cloudプロジェクトを共有する必要があります。 [公式手順](https://developers.google.com/apps-script/api/how-tos/execute)

## 5. 次にCodexへ渡すもの

次の2つを共有してください。いずれもブラウザへ公開される識別子で、パスワードやシークレットではありません。

- OAuthクライアントID
- Apps ScriptのスクリプトID

URLを受け取った後、アプリに以下を実装します。

- 同期URLの設定画面
- 選択中ルームの「サーバーへ保存」「サーバーから取得」
- `revision` による競合表示と、利用者による選択
- 保存・取得の状態表示

## 6. アプリ側での共有方法

同期は **選択中のルーム単位** です。最初に別端末へルームを渡すときだけ、JSONバックアップを使って同じ `roomId` を渡します。

### 最初の端末（端末A）

1. 共有したいルームを選ぶ。
2. **バックアップ → 選択中のルームをJSONに書き出す** を押す。
3. 同じ画面の **データ共有 → サーバーへ保存** を押す。
4. 「サーバーへ保存しました」と表示され、同期リビジョンが `1` になることを確認する。
5. 書き出したJSONファイルを、共有する端末へ安全な方法で渡す。

### 追加する端末（端末B）

1. JSONファイルを端末Bで開ける場所へ保存する。
2. アプリで **バックアップ → JSONを取り込む** を押し、ファイルを選ぶ。
3. 取り込まれたルームを選ぶ。
4. **データ共有 → サーバーから取得** を押す。
5. 「サーバーのデータを取り込みました」と表示され、同期リビジョンが端末Aと同じ値になることを確認する。

以後は、更新した端末で **サーバーへ保存**、別端末で **サーバーから取得** を押します。サーバーに保存する前に、別端末で新しい保存が見つかった場合は競合として停止します。先にサーバーから取得して内容を確認してください。

> 注意: この初期版では、サーバー上のルーム一覧を検索する機能はありません。端末Bで初めて共有ルームを選べるようにするため、最初の1回だけJSONを使います。

## 更新時の注意

Apps Scriptのコードを変更しただけでは、公開中の `/exec` は更新されません。変更後は **デプロイ → デプロイを管理 → 編集 → 新しいバージョン** を作成して再デプロイしてください。URLは通常そのまま使えます。
